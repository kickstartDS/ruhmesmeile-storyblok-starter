# ADR: Optoma → Template Upstreaming

> **Status:** Accepted (process ADR — appended as decisions are made)
> **Created:** 2026-07-21
> **Context:** [optoma-upstreaming-inventory.md](../internal/plans/optoma-upstreaming-inventory.md),
> [optoma-upstreaming-checklist.md](../internal/checklists/optoma-upstreaming-checklist.md)

This ADR records the architectural and process decisions made while upstreaming generic
improvements from the `optoma-website` client fork into the `ruhmesmeile-storyblok-starter`
template. New decisions are appended over time.

---

## ADR-001: Curated port instead of `git merge`

**Decision:** Do **not** merge `optoma/main` into `main`. Instead, port improvements as curated,
category-based batches (one branch + Changeset + PR per batch).

**Rationale:** The two histories diverged at `6e67004a` with ~858 changed files, the bulk of which
are Optoma-specific (imagery, brand tokens, product/NetSuite integration, CMS content). A merge
would drag all of that in and produce an unreviewable conflict surface. It also re-triggers a Git
LFS `404` because Optoma's LFS object OIDs (snapshots/screenshots) do not exist on this repo's LFS
server. A curated port keeps each change reviewable and revertable.

**Alternatives considered:**

- Full `git merge` then revert client bits — error-prone, huge conflict surface, LFS 404.
- `git cherry-pick` of Optoma commits — commits mix generic + client changes, so hunks would still
  need manual splitting; per-path checkout is cleaner.

---

## ADR-002: LFS artifacts are regenerated, never copied

**Decision:** `packages/design-system/__snapshots__/**` and `static/img/screenshots/**` are
regenerated locally (`build-storybook` → `create-component-previews`) after component changes are
ported. Optoma's LFS blobs are never pulled into this repo.

**Rationale:** These files are LFS-tracked. Their content lives on Optoma's LFS server keyed by OID;
those OIDs are absent from this repo's LFS server, so any checkout that smudges them fails with a
`404` (this is the root cause of the original failed merge). Regenerating produces correct blobs
backed by this repo's own LFS storage.

---

## ADR-003: Strip brand token _values_, keep structure

**Decision:** When a ported file touches design tokens (`branding-tokens.*`, `_fonts.scss`,
`fonts.css`, `token-dsa/dictionary/*`, per-component `_*-tokens.scss`), upstream only structural or
logic changes; the template's own token **values** are preserved. Optoma brand values are never
introduced.

**Rationale:** The template must remain brand-neutral (DS Agency default). Optoma color/typography
values would leak client branding into every downstream project seeded from the template.

---

## ADR-004: Batch A build wiring is coupled to Batch B (token-graph)

**Decision:** Split Batch A. Port the self-contained token-catalog tooling now
(`extractComponentTokenCatalog.cjs`, `extractSemanticTokenCatalog.cjs`, `componentTokensToCss.mjs`,
`tokensToCss.mjs` fix, `.d.ts` decls, and the corresponding `package.json` `component-token-catalog`
+ `semantic-token-catalog` scripts + rollup copy entries). **Defer** the `token-graph` build step,
the `@kickstartds/token-graph` `workspace:*` dependency, and the `token-graph.json` rollup copy to
Batch B, since they require the new `packages/token-graph` package to exist.

**Rationale:** Optoma's `package.json` build adds
`node ../token-graph/scripts/extractTokenGraph.mjs . src/token/token-graph.json` and a workspace
dependency on `@kickstartds/token-graph`. Wiring these into Batch A would break the build until
Batch B lands. Keeping Batch A self-contained means it builds green on its own.

**Consequence:** In Batch A, only add rollup copy entries for artifacts that exist after Batch A
(catalog JSONs + tooling); the `token-graph.json` copy entry is added in Batch B.

---

## ADR-005: Generated token catalogs are regenerated, not copied

**Decision:** `src/token/component-token-catalog.json`, `semantic-token-catalog.json`, and
`token-graph.json` are **generated by running the extract scripts in-template**, not copied from
Optoma.

**Rationale:** These artifacts embed the design system's actual token values/selectors. Optoma's
copies embed Optoma brand values (per ADR-003). Regenerating produces brand-neutral catalogs that
match the template's own tokens.

---

## ADR-006: Exclude Storybook brand font/favicon changes from tooling batch

**Decision:** Do not port `.storybook/main.ts` (Montserrat → Inter font-face swap) or
`.storybook/manager-head.html` (favicon size) in Batch A. These are brand choices, not tooling.

**Rationale:** The template's default brand is DS Agency (Montserrat). Swapping to Inter would
introduce Optoma's typography. Favicon wiring references brand assets. Any font-strategy change
belongs in a deliberate branding review, not the generic tooling batch.

**Open item:** `.storybook/preview.tsx` adds `a11y: { test: "off" }` — deferred pending decision
(the template emphasizes a11y audits). Tracked in the checklist REVIEW backlog.
